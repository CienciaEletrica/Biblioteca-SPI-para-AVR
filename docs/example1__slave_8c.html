Descrição detalhada

Exemplo SPI Slave: Resposta dinâmica baseada em processamento.

Autor
Tiago Henrique dos Santos - Ciência Elétrica

Funcionamento:

  1. O Slave aguarda o sinal de clock do Master.
  2. Ao receber um byte, a função slave_callback é executada.
  3. O Slave prepara o dado para a próxima transmissão usando spi_slave_preload.

Nota sobre Full-Duplex: No protocolo SPI, o dado que o Slave carrega no registrador agora só será deslocado para o Master na transferência seguinte. Por isso, usamos o callback para manter o pipeline de dados sempre atualizado.

int main ( void )

Ponto de entrada do exemplo Slave.

Observação
Configuração SPI Slave:
  • O pino SS deve ser configurado como entrada (feito automaticamente por spi_init).
  • O clock_div é ignorado, pois o Slave segue o clock do Master.

Primeiro byte de resposta.

Prepara o SPDR com um valor inicial (ex: 0x00) para que o Master não receba lixo eletrônico na primeiríssima leitura.

O Slave permanece em loop infinito. Toda a lógica de resposta é tratada de forma assíncrona pelo driver e pelo callback.

53 spi_config_t slave_cfg = {
54 .mode = SPI_MODE_SLAVE,

56 .cpol = 0, .cpha = 0,
57 .bit_order = SPI_ORDER_MSB_FIRST,
58 .use_interrupt = true,
59 .rx_callback = slave_callback,
60 .pins = {
61 .port = &PORTB,
62 .mosi_pin = PB3,
63 .miso_pin = PB4,
64 .sck_pin = PB5,
65 .ss_pin = PB2 // No Slave, SS deve ser entrada para o hardware SPI ativar
66 }
67 };

bool overflow )

Callback de recepção para o modo Slave.

Esta função é executada dentro da ISR logo após o término de um byte.

Parâmetros
[in]received_byteByte que o Master acabou de enviar.
[in]overflowIndica se o buffer interno falhou em armazenar o dado.
Observação
No modo Slave, usamos o callback para carregar a resposta que o Master lerá no próximo ciclo de clock.
